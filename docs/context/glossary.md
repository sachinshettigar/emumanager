# Glossary — durable domain vocabulary

Terms as this project uses them. If code and this file disagree, fix one of them.

| Term | Meaning |
| --- | --- |
| **AVD** | Android Virtual Device — a configured emulator instance (`~/.android/avd/<name>.avd` + `<name>.ini`). Created by `avdmanager`, run by `emulator`. |
| **Emulator (instance)** | Our user-facing word for an AVD plus the metadata we track about it (source profile, tags, timestamps). |
| **Emulator (engine)** | The `emulator` binary from the SDK `emulator` package (a fork of QEMU) that actually runs an AVD. |
| **System image** | The Android OS image an AVD boots. Identified by a **coordinate**: `system-images;android-<API>;<type>;<abi>`. |
| **Image type** | `default` (AOSP), `google_apis`, `google_apis_playstore`, `android-wear` / `wear`, `android-tv`, `android-automotive[_playstore]`. |
| **ABI** | CPU architecture of the image: `x86_64`, `arm64-v8a`. Must match (or be virtualizable on) the host. |
| **API level** | Integer Android platform version (e.g. 34 = Android 14). |
| **Device profile** | A hardware definition (screen size, density, RAM, sensors). Google ships many (`avdmanager list device`); users can define custom ones. Referenced in a recipe as `device.profile` (an id like `pixel_6`). |
| **cmdline-tools** | The "Command-line Tools" SDK package containing `sdkmanager` and `avdmanager`. Downloaded as `commandlinetools-<os>_<build>_latest.zip`. Java — needs a JRE. |
| **platform-tools** | SDK package containing `adb` (and `fastboot`). |
| **sdkmanager** | CLI that lists/installs/updates SDK packages and accepts licenses. We drive it; the user never types it. |
| **avdmanager** | CLI that creates/lists/deletes AVDs and lists device profiles. |
| **adb** | Android Debug Bridge — talks to a running emulator (`adb devices`, install APK, read boot state). |
| **Accelerator** | Host virtualization backend the emulator uses: **KVM** (Linux), **WHPX** / **AEHD** (Windows; HAXM is EOL), **Hypervisor.framework / HVF** (macOS). |
| **Elevated helper** | `emu-helper` — a separate small binary run with OS elevation, once, to do scriptable accelerator setup (enable WHPX, add user to `kvm`). |
| **.emuprofile** | A portable JSON **recipe** for an emulator. No binaries. Schema: `schemas/emuprofile/v1.schema.json`. See ADR 0004. |
| **Requirement diff** | Result of resolving a recipe against the local install: what's already present vs. what must be downloaded (with sizes). |
| **Registry** | The app's SQLite DB of emulators/images/profiles/jobs and our metadata. |
| **Reconcile** | Re-reading ground truth from `avdmanager list avd` / `adb devices` and updating the registry so it never lies about state. |
| **Job** | A tracked long-running operation (download, create, boot) that streams progress + log events to the UI. |
| **Port (in code)** | A trait in `emu-core` representing a side effect (`ProcessRunner`, `Downloader`, `HostProbe`, …) with a real impl and a test fake. |
| **Provider** | The trait the UI ultimately drives to manage emulators. Only `emu-android` implements it in v1. |
| **Data dir** | The per-user directory the app owns (`sdk/`, `avd/`, `db.sqlite`, `downloads/`, `profiles/`, `logs/`). Path from the `directories` crate. |
| **Bindings** | `src/lib/bindings.ts`, generated by `tauri-specta` from Rust command signatures. The only IPC surface. |
